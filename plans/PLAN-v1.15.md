# PLAN v1.15 — Recording indicator on the menu bar icon

## Context

Timelane has one shared Record/Stop timer (`RecordingTimer`, `Services/Timer`, owned by
`AppEnvironment.recordingTimer`, start time persisted in UserDefaults). While it runs, the main
window and the menu bar *panel* show it (red `RecordButton`, red `RecordingBlock` in "Logged
hours"). The menu bar *item itself* — the clock icon in the macOS menu bar — looks the same whether
or not a recording is running. Because the timer survives closing the window and relaunching the
app, the owner can easily forget a recording is running.

Goal: while `recordingTimer.isRunning`, the menu bar icon shows a **subtle small red dot** (like a
notification badge / "rec" light) on the clock. When nothing records, the icon is exactly the
current template icon.

## Current state

- `Timelane/App/TimelaneApp.swift`:
  `MenuBarExtra("Timelane", image: "MenuBarIcon") { ... }.menuBarExtraStyle(.window)`
- `MenuBarIcon` is a template image (`Assets.xcassets/MenuBarIcon.imageset`, 18 px @1x / 36 px @2x,
  `template-rendering-intent: template`), generated by `Tools/generate-app-icon.swift`.
- macOS renders a template image in the menu bar's foreground colour (black/white, dimmed when
  inactive) and **drops all colour**. So a red dot cannot simply be added to the template image,
  and a SwiftUI overlay (`ZStack` / `.overlay` with a red `Circle`) inside a `MenuBarExtra` label
  is flattened/monochromed too — the label is turned into a status-item image.

## Design

### 1. Pure state (unit-tested)

New `Timelane/MenuBar/MenuBarIconStyle.swift`:

```swift
/// What the menu bar item shows: the plain clock, or the clock with a red recording dot.
enum MenuBarIconStyle: Equatable {
    case normal, recording

    init(isRecording: Bool) { self = isRecording ? .recording : .normal }

    /// Accessibility / tooltip title of the menu bar item.
    var title: String { self == .recording ? "Timelane – Recording" : "Timelane" }
}
```

(Keep it this small; it exists so the mapping is testable and the label view has no logic.)

### 2. Image rendering

New `Timelane/MenuBar/MenuBarIconRenderer.swift` (`enum MenuBarIconRenderer`, `@MainActor`,
AppKit, no SwiftUI view types):

- `static func image(for style: MenuBarIconStyle) -> NSImage`
- `.normal` → `NSImage(named: "MenuBarIcon")` unchanged (template, `isTemplate == true`). This keeps
  today's behaviour pixel-for-pixel.
- `.recording` → a **non-template** `NSImage` of the same point size (18 × 18) built with
  `NSImage(size:flipped:drawingHandler:)`. A drawing-handler image is re-drawn on demand under the
  *current* appearance, so it still follows light/dark menu bars and wallpaper tinting:
  1. Draw the clock tinted with the menu bar foreground colour: draw the `MenuBarIcon` template into
     the rect, then fill the rect with `NSColor.labelColor` using `.sourceAtop` compositing (or
     `NSColor.labelColor.set(); rect.fill(using: .sourceIn)` on an offscreen copy). Use
     `labelColor`, not `.black`, so it is white on a dark menu bar.
  2. Punch a small transparent ring where the dot goes, so the dot does not visually merge with
     the clock outline: fill a circle of diameter ~8 pt with `.clear` compositing
     (`NSGraphicsContext.current?.compositingOperation = .clear` or
     `NSBezierPath(ovalIn:).fill()` after setting `.copy` with `NSColor.clear`).
  3. Fill the red dot: `NSColor.systemRed`, diameter **~6 pt**, centred in that ring, at the
     **bottom-right** corner of the 18 pt canvas (e.g. dot rect `x: 12, y: 0, w: 6, h: 6` in
     unflipped coordinates; ring rect 1 pt larger on each side, clipped to the canvas is fine).
  4. Set `image.isTemplate = false`. Cache the two images in `static let`s (the drawing handler
     still re-renders per appearance, caching only avoids reallocating).
- Keep it **subtle**: small dot, no animation/pulsing, no text, no change to the item width.

If while implementing it turns out the menu bar shows the recording image fully monochrome (i.e.
SwiftUI still forces template rendering), the fallback is: render the label as
`Image(nsImage:)` with `.renderingMode(.original)`; if that is still monochrome, report it in the PR
description instead of switching to an `NSStatusItem` rewrite — that is a bigger change the owner
must decide on.

### 3. Label view

New `Timelane/MenuBar/MenuBarLabel.swift`:

```swift
/// The menu bar item: the clock icon, with a red dot while the Record timer runs.
struct MenuBarLabel: View {
    let timer: RecordingTimer

    var body: some View {
        let style = MenuBarIconStyle(isRecording: timer.isRunning)
        Image(nsImage: MenuBarIconRenderer.image(for: style))
            .accessibilityLabel(style.title)
    }
}
```

`RecordingTimer` is `@Observable`, so reading `timer.isRunning` in `body` makes the label update
the moment Record/Stop is pressed — from the main window, the menu bar panel or ⌘R. Add a
`#Preview` (AGENTS.md rule) showing both styles side by side, using
`AppEnvironment.preview().recordingTimer` for one and a started timer for the other (or just two
`Image(nsImage:)`s if a started preview timer is awkward — the preview must not touch real
UserDefaults; `AppEnvironment.preview()` uses the in-memory store).

### 4. Wire it up

`Timelane/App/TimelaneApp.swift`: replace the `image:` initializer with the label-closure form:

```swift
// Same clock as the app icon (template image from Tools/generate-app-icon.swift);
// a red dot is added while the Record timer runs.
MenuBarExtra {
    MenuBarContentView(environment: environment)
        .environment(environment)
} label: {
    MenuBarLabel(timer: environment.recordingTimer)
}
.menuBarExtraStyle(.window)
```

Nothing else changes: the panel, `PanelOpenObserver`, the timer and tracking are untouched.
No new dependencies, no schema change.

## Tests (Swift Testing, `TimelaneTests/MenuBarIconTests.swift`)

- `MenuBarIconStyle(isRecording: false) == .normal`, `(isRecording: true) == .recording`.
- `title` is "Timelane" / "Timelane – Recording".
- Renderer: `.normal` image `isTemplate == true` and size 18 × 18; `.recording` image
  `isTemplate == false` and size 18 × 18 (same point size → the menu bar item does not jump).
- Renderer `.recording` produces red: render it into an `NSBitmapImageRep` (e.g. 36 × 36 for @2x)
  and assert a pixel inside the dot area (bottom-right) is reddish (red ≫ green/blue, alpha > 0.5).
  Keep this test robust: sample the dot centre only.
- Label follows the timer: with `RecordingTimer(store: InMemoryRecordingTimerStore(), clock: fake)`,
  `MenuBarIconStyle(isRecording: timer.isRunning)` is `.normal`, after `start()` `.recording`, after
  `stop()` `.normal` again. (Use the in-memory store — never the UserDefaults store in tests.)

Tests must not need signing identity or local state (they run in CI with ad-hoc signing).

## Manual checks (for the owner — agents cannot see the UI)

- Not recording: menu bar icon is the plain clock, identical to before (light and dark menu bar).
- Press Record (main window, ⌘R or menu bar panel): a small red dot appears at the bottom-right of
  the clock immediately; the clock itself stays black/white matching the menu bar.
- Switch macOS between light and dark appearance while recording: the clock part follows.
- Press Stop: the dot disappears immediately.
- Quit and relaunch while recording: the dot is there right at launch (timer is persisted).
- The menu bar panel still opens/closes normally when clicking the icon.
